# platforms/ — дескрипторы версий платформы 1С

Каждый файл описывает специфику одной версии: бинарный путь, строка подключения, логи, клиенты тестирования.

## Поля

| Поле | Обязательно | Описание |
|---|---|---|
| `ВерсияПлатформы` | да | Версия платформы 1С (например `"8.3.27"`) |
| `КаталогПоискаВерсииПлатформы` | да | Путь к `1cv8` (`C:\Program Files\1cv8` или `(x86)\1cv8`) |
| `СтрокаПодключенияКБазе` | да | `ENTERPRISE /F.\ServiceBases\vXXX...` |
| `ВыводитьСообщенияВФайл` | да | Лог-сообщений 1С: `./ServiceBases/Messages <ver>.txt` |
| `ИмяФайлаЛогВыполненияСценариев` | да | `./tools/ServiceBases/log<ver>.txt` |
| `КлиентыТестирования` | да | Массив с одним объектом (ПутьКИнфобазе, ТипКлиента, порт…) |
| `platformExcludeTags` | да | Теги тестов, которые нельзя гонять на этой версии: `["IgnoreOn8327"]` |
| `_webКлиентыТестирования` | нет | Web-клиент для flavor=web (URL с именем базы) |

## Добавить платформу

1. Создать `platforms/<ver>.json` по образцу `8.3.27.json`.
2. Заполнить все обязательные поля.
3. В `platformExcludeTags` добавить тег `IgnoreOn<ver>` (или оставить `[]` если тегов нет).
4. Проверить: `oscript tools/checks/check.os --platform <ver> --flavor uf --dry-run`.

## Пример

```json
{
   "ВерсияПлатформы": "8.3.99",
   "КаталогПоискаВерсииПлатформы": "C:\\Program Files\\1cv8",
   "СтрокаПодключенияКБазе": "ENTERPRISE /F.\\ServiceBases\\v83ServiceBase8399",
   "ВыводитьСообщенияВФайл": "./ServiceBases/Messages 8.3.99 UF.txt",
   "ИмяФайлаЛогВыполненияСценариев": "./tools/ServiceBases/log8399.txt",
   "КлиентыТестирования": [
      {
         "Имя": "Этот клиент",
         "ПутьКИнфобазе": "/F.\\ServiceBases\\v83ServiceBase8399",
         "ДопПараметры": "",
         "ТипКлиента": "Тонкий",
         "ИмяКомпьютера": "localhost",

}
```

## Compat-8.2

`compat-8.2-uf.json` и `compat-8.2-of.json` — особые платформы для баз в режиме совместимости с 1С 8.2. Описание выбора оформления см. в блоке ниже.

### Почему два дескриптора, а не один

Compat-8.2 делится на два принципиально разных стенда:
- **uf** (управляемые формы) — платформа 8.3.21, 32-bit тонкий клиент, база `v82ServiceBase82`.
- **of** (обычные формы) — платформа 8.3.6, 32-bit толстый клиент (`ЗапускатьТолстыйКлиент=Истина`), дополнительный флаг `/RunModeOrdinaryApplication`. Пути в of используют `.\..` (Windows-стиль) в отличие от остальных.

Они различаются настолько (версия, тип клиента, пути), что разбивка на два дескриптора + соответствующий flavor (uf/of) проще и понятнее, чем один комбинированный.
