# flavors/ — дескрипторы флейворов (тип клиента / режим)

Флейвор описывает тип клиента 1С и специфические настройки, не зависящие от версии платформы.

## Поля

| Поле | Обязательно | Описание |
|---|---|---|
| `flavorExcludeTags` | да | Теги тестов, которые нельзя гонять в этом флейворе: `["IgnoreOnUFBuilds"]` |
| прочие поля VBParams | нет | Перекрывают defaults и платформу (например `ДелатьЛогВыполненияСценариевВЖР`) |

## Добавить флейвор

1. Создать `flavors/<name>.json`.
2. Добавить `flavorExcludeTags` (можно пустой массив `[]`).
3. Добавить любые VBParams-поля, специфичные для этого флейвора.
4. Проверить: `oscript tools/checks/check.os --platform 8.3.27 --flavor <name> --dry-run`.

## Пример

```json
{
   "_description": "Server-клиент (RPС-режим). Тестирование серверного соединения.",
   "flavorExcludeTags": ["IgnoreOnServer"],
   "КлиентыТестирования": [
      {
         "Имя": "Этот клиент",
         "ПутьКИнфобазе": "Srvr=localhost;Ref=ServiceBase8327;",
         "ДопПараметры": "",
         "ТипКлиента": "Тонкий",
         "ИмяКомпьютера": "localhost",
         "ПортЗапускаТестКлиента": "1538",
         "АктивизироватьСтроку": "Истина"
      }
   ]
}
```

## Composite-флейвор

Composite объединяет два флейвора в одном дескрипторе. Пример: `uf-nosync.json` = uf + nosync.

```json
{
   "_description": "Composite: uf + nosync.",
   "ВыполнятьШагиАсинхронно": "Истина",
   "flavorExcludeTags": ["IgnoreOnUFBuilds", "IgnoreOnNoSync"]
}
```

Правило: `flavorExcludeTags` composite = объединение тегов всех входящих флейворов. Остальные поля — как у приоритетного флейвора (или merge вручную).
